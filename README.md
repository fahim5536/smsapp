## ✨ At a Glance

Tuition Manager replaces the paper register every private tutor in Bangladesh still carries. A teacher signs in with **just a phone number** (anonymous Supabase auth, no password), and instantly gets a live workspace for their students, attendance sheets, monthly fee ledger, weekly class routine — and one-tap SMS drafts to parents.

| | | |
|:---:|:---:|:---:|
| 📱 **Phone-only login**<br/>No password, no email. OTP-free anonymous auth linked to the teacher's phone. | 🧑‍🎓 **Live student registry**<br/>Realtime stream, instant search, fee badge per student, cascade-safe delete. | ✅ **Attendance sheets**<br/>Mark Present / Absent / Leave per day, with notes. One row per student per day. |
| 💰 **Fee ledger**<br/>Due → Partial → Paid per month, paid-date tracking and a monthly collection report. | 🗓️ **Class routines**<br/>Day-wise schedule with topic, time and location — editable in a dialog, streamed live. | 💬 **Parent SMS**<br/>Fee reminders, attendance alerts and routine notices pre-filled into the device SMS app. |

## 🧰 Tech Stack

| Layer | Choice | Why |
|---|---|---|
| **UI** | Flutter `3.x` + Material 3 | Single codebase for Android, Web and Desktop. |
| **State** | `flutter_riverpod 3.4.3` | Compile-safe providers, `StreamProvider` for realtime tables, `Notifier` signals for auth refresh. |
| **Backend** | `supabase_flutter 2.17.2` | Postgres + Auth + Row Level Security + Realtime, zero servers to run. |
| **Fonts / i18n** | `google_fonts 8.2.1`, `intl 0.20.3` | Outfit typeface, Bengali (`bn`) date & currency formatting (`৳`). |
| **SMS** | `url_launcher 6.3.2` | Opens the native SMS composer pre-filled — no SMS permission, no gateway cost. |
| **Local prefs** | `shared_preferences 2.3.2` | Lightweight on-device session helpers. |

## 🗄️ Database Schema

Five Postgres tables, all behind Row Level Security, defined in [`supabase/schema.sql`](supabase/schema.sql).

```
teachers ──< students ──< attendance
                 │
                 ├──< fees
                 └──< routines
```

| Table | Key columns | Constraint |
|---|---|---|
| `teachers` | `auth_user_id`, `full_name`, `phone` | `phone` unique; writes limited to own row |
| `students` | `teacher_id`, `name`, `guardian_phone`, `class_name`, `subject`, `monthly_fee`, `schedule` | indexed on `teacher_id`, `name` |
| `attendance` | `student_id`, `date`, `status`, `note` | `unique(student_id, date)` |
| `fees` | `student_id`, `month (YYYY-MM)`, `amount`, `paid_amount`, `status` | `unique(student_id, month)` |
| `routines` | `class_name`, `day`, `day_of_week`, `start_time`, `end_time`, `topic`, `location` | realtime-enabled |

`students` and `routines` are added to the `supabase_realtime` publication so the UI updates live via `.stream()`.

## 🚀 Getting Started

### 1 · Prerequisites
- Flutter SDK with **Dart `^3.13.4`**
- A [Supabase](https://supabase.com) project (free tier is enough)
- Android Studio / VS Code, or just a terminal

### 2 · Clone & fetch

```bash
git clone https://github.com/fahim5536/smsapp.git
cd smsapp
flutter pub get
```

### 3 · Create the database

Open **Supabase Dashboard → SQL Editor → New query**, paste the whole [`supabase/schema.sql`](supabase/schema.sql) file and run it.

> ⚠️ The script starts with `DROP TABLE` statements — run it only on a fresh project or disposable data.

Then create the re-login helper RPC in the same editor:

```sql
create or replace function public.login_teacher(p_phone text)
returns void
language plpgsql
security definer
set search_path = public
as $$
begin
  update public.teachers
  set auth_user_id = auth.uid(), updated_at = now()
  where phone = p_phone;
end;
$$;
```

### 4 · Point the app at your project

Credentials are injected at build time so secrets never live in source:

```bash
flutter run \
  --dart-define=SUPABASE_URL=https://YOUR-PROJECT.supabase.co \
  --dart-define=SUPABASE_ANON_KEY=your-anon-key
```

### 5 · Run

```bash
flutter run -d chrome        # web
flutter run                  # connected Android device
```

## 💬 How SMS Actually Works

The app never sends SMS silently and requests **no** `SEND_SMS` permission. `SmsService` builds an `sms:<phone>?body=<message>` URI and hands it to `url_launcher`, which opens the **device's native messaging app** with the recipient and Bengali message already filled in — the teacher just taps send.

- The sending SIM is whatever the phone's messaging app uses; it is **not** tied to the account phone number.
- Bulk sends loop recipients with a 100 ms gap so the composer isn't flooded.
- Android 11+ package visibility for `sms:` / `smsto:` intents is already declared in `AndroidManifest.xml`.
- On Web there is no SMS app, so this flow is a no-op there — test on a real device.

```
lib/
├── main.dart                     # App entry + AuthGate (owns Login ⇄ Home switch)
├── core/
│   ├── config/supabase_config.dart   # --dart-define credentials + table names
│   ├── services/supabase_service.dart# client bootstrap + auth state stream
```
